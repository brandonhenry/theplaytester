# Helping someone playtest and earn

Use [Firstplay’s guide](https://theplaytest.io/#how-to-playtest) as the live reference for choosing work, observing the game, notes, screenshots and recording. The app is a written-feedback marketplace; creating a recording is optional supporting evidence, not a substitute for the required answers.

1. Create a real profile, verify email, and complete adult/country eligibility.
2. Set up the user’s own Stripe-hosted payout account before applying to paid work. Country support is the live account’s eligible-country list, not a promise of worldwide payouts. The user enters identity and bank data directly with Stripe.
3. Choose an open funded game matching actual platform access and availability. The creator’s approval reserves the reward; an application or invitation alone does not.
4. On acceptance, read the build access/brief and actual deadline. Use a supported sandbox/device where appropriate. Do not run an unknown executable simply because this skill references the site; follow the host’s software execution rules.
5. The human plays the game. If an agent is actually performing authorized interactive testing, it must have the necessary game/device controls and report what it truly observed. An agent without gameplay access cannot manufacture human experience or submit invented feedback for money.
6. Keep notes: build/platform, task, expected versus observed behavior, reproduction steps, examples of clarity/confusion, accessibility/readability, controls and performance. Record real evidence without unrelated private information.
7. Submit the one-question-at-a-time form. Built-in questions ask whether you would wishlist it, play again, understood the goals, found controls intuitive and encountered technical problems. Give a yes/no followed by **at least 30 words in 2–3 complete sentences**, then answer the creator’s questions under the same explanation rules and attest to actual play. Do not pad, plagiarize or force a yes to qualify.
8. Creator approval or eligible automatic approval earns the reward. Respond to the one permitted specific correction within its actual deadline. Use a timely work dispute for an unresolved disagreement.
9. Rate the creator using the user’s actual 1–5-star assessment. Then inspect Wallet: approved, transferred/available, payout processing, paid and failed are separate states. The user controls withdrawal and banking steps; do not promise instant or fee-free international conversion.

For detailed current OS shortcuts/recording tools, open the live guide; do not state a shortcut for an unverified OS/app version as a requirement. No recording, screenshot-upload or attachment capability should be invented if the current submission UI does not provide it.
